# T-14 ShipFast implementation plan

Goal: book PrintHub handovers, simulate courier outcomes and gate repeat reships.

Architecture: shared schemas and zone prices, clock-driven in-memory courier state,
ordered signed callbacks, transaction-scoped shipment services with order locks.
Reships use a unique source and per-order sequence. The existing approval engine
executes second/subsequent reships with the same booking function, revalidating the
source at decision time. No public approval bypass.

- Write failing simulator tests for zones/prices, timing, three failed attempts,
  RTO cost, 0.5% loss, idempotence and ordered retries; implement shared/sim modules.
- Write store integration tests for printing readiness, concurrent bookings,
  callbacks/order transitions, first reship, repeated 202 and founder decisions.
  Implement schema migration, services, routes and executor registration.
- Update OpenAPI, events and timing decisions. Validate lint, typecheck, tests and
  migration drift on switchgear_codex. Sync main, open PR and hand to reviewer.

Review focus: external acceptance with lost response; no courier booking before
approval; duplicate/stale callbacks and approvals; reship count versus delivery
attempt count; one RTO surcharge; order status at failed delivery, RTO and loss.

Validation before main sync: lint, typecheck, 248 tests, 10 migrations, drift check,
store build and all 13 Playwright tests pass. A live HTTP flow with an accelerated
clock verified checkout/payment, PrintHub handover, three delivery failures/RTO,
first reship, second reship 202, founder approval exactly once and latest-AWB tracking.
