# T-15 Demo clock and order generator implementation plan

**Goal:** Run a controllable, reproducible demo using existing checkout and partner flows.
**Spec:** docs/tasks.md T-15; docs/spec.md §9; docs/architecture.md demo clock.
**Architecture:** One mutable clock shared by partners. A serial generator tracks business deadlines and uses HTTP catalogue, checkout and payment opening; PayMock sends normal signed webhooks. Founder Basic auth protects the simulator control page and mutation APIs using the existing test founder environment credentials. No database access from sim.
**Choices:** 144× is demo speed. Default generator off, explicit start; 30 orders/business day, no backlog while stopped. Seeded PRNG controls carts, fictional customers and shuffled 100-outcome batches (95/4/1). State is in memory, reset seed only while stopped; no dependency on unfinished T-12 admin.
**Tech stack:** Existing TypeScript, Fastify, zod (validation; add to sim workspace), Next route handlers.

- [x] Test deterministic cadence, outcome mix, stop/resume, overlapping ticks and HTTP failures; implement generator with bounded serial work and observable error state.
- [x] Add documented catalogue reads and database integration tests for generated orders and signed payments. Test pending deadlines across speed changes.
- [x] Document controls/API/environment and decisions. Merge latest main, run lint, typecheck, tests with switchgear_codex, build and live HTTP demo; commit, open PR, hand to reviewer.

**Review focus:** auth/CSRF; business time continuity; speed changes on pending work; no duplicate checkout after ambiguous errors; stop/reseed with an in-flight order; current published SKUs and fake data only. Already placed orders finish payment even if generation is stopped. A checkout network error is reported and not retried automatically, since checkout has no idempotency contract.
