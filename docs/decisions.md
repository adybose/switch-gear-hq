# Decisions

Short, dated log. Newest first. Append; don't rewrite history.

| Date | Decision | Why |
| --- | --- | --- |
| 2026-11-06 | Repo is `switch-gear-hq`, a single npm-workspaces monorepo | One clone + `docker compose up` for judges |
| 2026-11-06 | Money stored as integer paise | Avoid float rounding in ledger and GST |
| 2026-11-06 | Approval gates enforced by the store API, not by agents | Agents can't bypass or self-approve |
| 2026-11-06 | Gatekeeper is plain code (no AI) | Event routing and approvals must be predictable |
| 2026-11-06 | `AGENTS.md` is the source of truth; `CLAUDE.md` imports it | One set of rules for Claude Code and Codex |
| 2026-11-06 | Skills in `.agents/skills/`, linked from `.claude/skills` | Codex and Claude Code read the same files |
| 2026-11-06 | Chat app is Slack (free plan, autocomplete off) | Founder knows Slack; no paid features needed |
| 2026-11-06 | Builder on Claude Code, Reviewer on Codex | Every PR checked by a second model |
| 2026-11-06 | PayMock instead of a real gateway's test mode | Runs with no accounts or keys; adapter allows swapping later |
| 2026-11-07 | Docker and CI use Node 22 LTS; code still supports Node 20.19+ | Node 20 is past end of life; `engines` keeps 20 working locally |
| 2026-11-07 | TypeScript pinned to 5.9, Vitest to 4.x | typescript-eslint doesn't support TS 7 yet; Vitest 5 drops Node 20 |
| 2026-11-07 | One root `Dockerfile` with a target per service; sim and gatekeeper run TS via `tsx` | No per-app build step; workspaces share one `npm ci` layer |
| 2026-11-07 | Workspace packages export TypeScript source (no build); Next transpiles `@switch-gear/shared` | Fewer moving parts for a hackathon monorepo |
| 2026-11-07 | Prettier skips Markdown, `docs/`, `api/` and agent folders | Don't reformat hand-written docs and the API contract |
| 2026-11-07 | Prisma 7 with the `pg` driver adapter; client generated to `apps/store/src/generated` on `npm install` | No native engine download; works on Node 20 and Alpine |
| 2026-11-07 | Ledger balance enforced twice: `postLedgerTxn()` check and a deferred Postgres constraint trigger | A bug or raw write can't leave unbalanced books |
| 2026-11-07 | DB tests skip without `DATABASE_URL`; CI runs them against a Postgres service | `npm test` still passes on a fresh clone with no database |
| 2026-11-07 | Store container runs `prisma migrate deploy` on start | `docker compose up` works on a fresh clone without extra steps |
| 2026-11-07 | A test checks Prisma enums against `api/openapi.yaml`; CI fails if migrations drift from `schema.prisma` | Contract and database stay in step |
| 2026-11-07 | Founder login is a `founder.login` Setting row (email + scrypt hash), not a User table | One account; no schema change for it |
| 2026-11-07 | `.env.local.keys` is written once; reseeds and demo resets reuse its keys, and any key not in it is revoked | Agents' `sg` configs survive `demo:reset`; deleting the file rotates every key |
| 2026-11-07 | `db:seed` only adds missing rows; `demo:reset` truncates everything (in one transaction) and seeds | Seeding a live DB never clobbers changes; reset is repeatable |
| 2026-11-07 | Vitest runs test files one at a time; with `DATABASE_URL` set, `npm test` leaves the DB in the demo seed state | DB tests share one Postgres and the reset test truncates it |
| 2026-11-07 | The ₹2,500 GST limit is the pre-GST value per piece (founder decision; up to ₹2,625 including 5% GST); tax is the inclusive price minus the rounded taxable value | Matches how apparel GST works; the parts always add back up to the price |
| 2026-11-07 | Intra-state GST splits into equal CGST/SGST halves, odd paisa to SGST | Integer paise; deterministic |
| 2026-11-07 | The business clock syncs with the sim every 5 s and runs forward locally in between; real time if the sim is down | No sim call per request; the store keeps working without the sim |
| 2026-11-07 | Storefront pages read the catalogue from Postgres per request (`connection()`); policy pages are static | `next build` needs no database; catalogue changes show immediately |
| 2026-11-07 | Cart lives in the browser (localStorage); checkout re-prices every line on the server | No cart table or session; client prices are never trusted |
| 2026-11-07 | Mockups are SVGs generated at `/artwork/<slug>.svg?colour=<colour>` from the design name | Original artwork only; one URL per design, as the seed stores |
| 2026-11-07 | The 3-tee 10% discount and a discount code don't stack; the bigger one applies (founder confirmed) | Simple to explain; caps discounts at the code limit |
| 2026-11-07 | Free shipping (₹999+) is measured on goods after discounts; shipping is taxed at the highest GST rate in the cart (founder confirmed) | Matches what the customer pays; recorded in spec §2 and §6 |
| 2026-11-07 | ShipFast service area is a shared rule (`packages/shared/src/shipping.ts`): PINs starting 9, 744, 68255 and 194 are blocked; 560 is same city, 5/6 same zone, rest national | Store checkout and the sim (T-14) agree without a network call |
| 2026-11-07 | Orders are numbered from a Postgres sequence (ORD-1001 up); demo reset restarts it | No gaps or races from counting rows |
| 2026-11-07 | Orders store their own delivery details; the Customer row only links orders by email and checkout never updates it | Public checkout can't change another order's address; repeat-refund rule (spec §8) still sees one customer |
| 2026-11-07 | Order confirmation links carry an HMAC token (`ORDER_LINK_SECRET`); until PayMock (T-07) `paymentUrl` is that page | Order numbers are guessable; the token isn't |
| 2026-11-07 | Added `POST /checkout/quote` (in openapi.yaml) | Checkout page shows totals, code and PIN problems before the order is placed |
| 2026-11-07 | Event writers take a transaction-scoped advisory lock, so outbox `seq` order equals commit order | A poller paging by `after=<seq>` can never skip an event that commits late; throughput is fine for the demo |
| 2026-11-07 | Webhook dedupe via a `WebhookReceipt` table (unique partner + eventId), written in the handler's transaction | Exactly-once effects; a failed handler leaves no receipt, so the partner's retry works |
| 2026-11-07 | `GET /events` accepts any valid API key until T-09 adds scopes | Not public in the meantime |
| 2026-11-07 | Webhook secrets fall back to the `.env.example` test values when unset | A fresh clone works; unsigned or wrongly signed calls are still rejected |
| 2026-11-07 | PayMock payment rows are written when the gateway reports an outcome (captured/failed), not when the pay page opens | Every Payment row comes with its event; opening the page changes no store state |
| 2026-11-07 | `paymentUrl` is a store route (`/pay/ORD-…`) that opens the PayMock payment on demand; the order page links to it as "Pay now" | Checkout doesn't depend on the sim being up; a customer can retry |
| 2026-11-07 | Added `order.cancelled` (spec §10) for orders not paid within 30 business minutes | No existing event fits a timeout; `payment.failed` stays for gateway failures |
| 2026-11-07 | PayMock "Pending" always resolves to captured, within 5 business minutes | Spec says pending resolves; failures have their own button |
| 2026-11-07 | Store refuses a capture for a non-placed order or wrong amount with 409; PayMock then voids it | A late capture can't revive a cancelled order or take money for it |
| 2026-11-07 | Payment stores the 2% fee and its 18% GST separately (`feePaise`, `feeGstPaise`) | The ledger (T-16) books the fee as expense and its GST as input credit |
| 2026-11-07 | PayMock keeps its state in memory; the sim clock speed comes from `SIM_CLOCK_SPEED` until T-15 | Sim restarts are rare in the demo; the unpaid timer cleans up |
| 2026-11-07 | PayMock keys payments on the store's internal order id (`orderRef`) and echoes it in webhooks; the store matches id and number | Order numbers restart after `demo:reset`; a stale payment can't open or pay a new order |
| 2026-11-07 | Settlement claims payments with one conditional `UPDATE … RETURNING` | Two racing batches can't both settle (and report) the same payment |
| 2026-11-07 | Anything waiting on a human gets a real-time minimum. Unpaid orders are cancelled after 30 business minutes or 5 real minutes, whichever is longer (founder decision); `Order.createdAt` records real time for it, and PayMock's deadline follows the same rule | At demo speed 30 business minutes is about 12 real seconds, too short for a person to pay |
| 2026-11-07 | The store sends PayMock both unpaid deadlines (`expiresAt` business, `minExpiresAt` real); both sides use `isUnpaidExpired()` | Neither side needs the clock speed, so PayMock can't expire a payment before the store would cancel the order |
| 2026-11-07 | API scopes are `<name>:read` / `<name>:write` in `apps/store/src/server/scopes.ts`; routes call `authorize(db, request, scope)` (401 bad key, 403 missing scope). `GET /events` needs `events:read`, held only by `hq` and `founder` | One scope per endpoint keeps the table in architecture.md the single source; Gatekeeper uses the founder key, so no other key needs the event feed |
| 2026-11-07 | Approval gates are pure checks in `apps/store/src/server/gates.ts` over limits loaded from `Setting`; over-limit routes call `requestApproval()` and answer 202. Each gated action registers an executor with `registerApprovalAction()`, which runs on approve in the decision transaction | The gated endpoints arrive in T-14/18/19/21; they reuse one gate engine instead of each writing its own |
| 2026-11-07 | A decision flips `pending` → decided with one conditional update; the executor runs in the same transaction, so a failing action leaves the request pending. Approving an action with no executor is refused (409 `action_not_supported`); reject needs a reason | Exactly-once execution under concurrent clicks from Gatekeeper and the admin console |
| 2026-11-07 | Refund gate: an order cancelled before printing passes regardless of amount or repeats; a 2nd refund means the customer already had one within `approval.refund.repeatWindowDays`. Discount codes running longer than 7 days also need approval. Ad spend needs approval when this week's committed budget plus the request exceeds `budget.ads.weeklyPaise` | Reading of spec §8 where the table leaves the edge open |

| 2026-11-07 | PrintHub emits `printjob.status` for creation and each status transition; `printjob.misprint` and `printjob.late` remain actionable events | All print and order changes have an outbox trail; handed_over leaves the order printing until ShipFast (T-14) accepts it |
| 2026-11-07 | PrintHub uses the shared sim clock, exposed read-only at `/sim/clock`; controls remain T-15. Production starts after 1 business hour, QC at 1 day, packing at 1.5 days and handover at 1.9 days from its capacity slot | Both store SLA timers and partner progression see the same time |
| 2026-11-07 | PrintHub capacity is 50 jobs per UTC business-date bucket; overflow queues to the next day. Invalid HTTP artwork references reject; premium olive XXL simulates missing blanks; every item independently has a 3% misprint chance | Predictable failure cases and queue-driven lateness, without scenario controls (T-27) |
| 2026-11-07 | A misprint permits one successor per attempt, reprinting the whole order for zero cost. Other failed jobs stay terminal for agent investigation | Free remediation cannot be used to submit duplicate paid work; SKU defects stay in the misprint event |
| 2026-11-07 | PrintHub stores requests in memory keyed by internal order ID + attempt. Identical retries reuse acceptance, conflicting payloads fail. Status webhooks retry in order on network/5xx and initial unknown-job callbacks | An ambiguous create response can roll back locally and be retried safely; sim restart loses partner memory, as with PayMock |
| 2026-11-07 | Print jobs store business acceptedAt/dueAt and a lateReportedAt claim. An active job strictly past two days emits late once, even with multiple store timers | Wall-clock createdAt remains for auditing; transaction and order locks prevent duplicate alerts/reprints |

| 2026-11-07 | ShipFast prices and 1/3/5-day transit use the existing shared PIN zones; a fixed fictional Bengaluru pickup and 250g per tee are sent to the partner | Store and courier serviceability agree; weight does not alter the specified prices |
| 2026-11-07 | ShipFast loss is sampled at 0.5% per booking. Each delivery attempt fails at 10% (unspecified in spec); up to two next-day retries, then RTO one day after failure three | Deterministic injected random supports tests; default failure mix exercises remediation |
| 2026-11-07 | Shipment.sequence counts bookings/reships; attempts counts deliveries on one AWB. First reship is allowed by Setting; second and later wait for the founder. Pending duplicates reuse one request | Delivery retries cannot change or bypass the reship gate |
| 2026-11-07 | Courier acceptance sets shipped; delivery sets delivered; RTO sets returned and doubles that booking cost. Loss emits shipment.failed(reason lost), retaining shipped until remediation | Existing OrderStatus has no lost state; no false delivery or return is recorded |
| 2026-11-07 | Every courier change emits shipment.status, plus actionable delivered/failed/rto events. Store order locks and unique source/sequence ensure one successor, and the approval executor revalidates before booking | Concurrent booking, reship and approval calls cannot duplicate courier work or revive stale orders |
| 2026-11-07 | ShipFast follows PrintHub's in-memory idempotent booking and ordered callback retries. The decision transaction allows 15 seconds for partner calls and rollback; an ambiguous response reuses the same booking on retry | Approvals stay pending when booking fails; no shipment exists before approval; a lost response cannot duplicate an AWB |
| 2026-11-07 | `sg` reads `SG_API_URL` (API base; `/api/v1` is added if missing) and `SG_API_KEY` from the environment first, then the working folder's `.env`. The older `SG_STORE_URL` still works. Amounts are typed in rupees and sent as paise; usage errors exit 2, API and network errors exit 1 | Matches the T-23 acceptance criteria; each agent folder has its own `.env` and key, and money stays integer paise |
| 2026-11-07 | Gatekeeper posts every event to `#events`, then to the owning room mentioning its role (`apps/gatekeeper/routes.ts`, spec §10). "Also told" rooms get the same line with no mention, so no second agent is woken; the requesting department is mentioned in its own room when its approval is decided | Keeps agent work to the owner of each event; the owner hands off when it matters |
| 2026-11-07 | Gatekeeper's Switch connection claims only `#approvals` (scope single, filter addressed) and acts only on `approve APR-n` / `reject APR-n <reason>` from `SWITCH_FOUNDER_ID`, an exact match on the sender's participant id. Other rooms are posted to through `POST /agents/{id}/message` | One room to listen in, one identity that can decide; display names can be copied, participant ids can't |
| 2026-11-07 | Gatekeeper never skips work. The event cursor (in `GATEKEEPER_STATE_FILE`) moves only after every post for an event succeeds, and the posts already made are saved, so a retry doesn't repeat them. A post to a room Gatekeeper isn't in fails: the event waits, and the rooms are looked up again until it can be delivered. A timer's state is saved only after its post. A founder message whose handling fails is retried in order, and the Switch cursor doesn't pass it. Once the store has answered a decision, only the reply is retried, and a store 5xx is retried, not answered. Timers fire when the sim's business date (IST) or ISO week rolls over | A missing room or an outage delays work instead of silently dropping it; the store runs a decision at most once, so retrying is safe |

| 2026-11-07 | T-15 controls live at sim `/sim/admin` with test founder Basic auth and same-origin writes; runtime state remains in memory, separate from legacy seed clock/flag placeholders | T-12 admin is not a dependency; sim never accesses the store DB, and controls ship without requiring an unfinished admin session system |
| 2026-11-07 | Generator defaults off, runs 30 slots/business day with seeded carts and shuffled exact 95/4/1 outcome batches; stop discards backlog and reseed requires stopped/idle | Repeatable demo inputs and no traffic bursts or seed races; checkout errors are reported without automatic retry because checkout is not idempotent |
| 2026-11-07 | Added the previously documented public catalogue read routes as T-15's SKU source | Simulator chooses published products and active variants via HTTP, without importing seed data or reading Postgres |
